## 已修复：浮窗边框与几何计算不一致

`CompanionFloat` 的宽高由几何函数计算，但 CSS 默认使用 content-box，1px 边框会额外增加总宽高。390px 窄屏测试测得 x=32、实际宽=360，右边缘为 392px，超出视口 2px。根容器增加 `boxSizing: 'border-box'` 后，同一脚本测得宽=358、右边缘=390，断言通过。现有纯几何单测与真实浏览器尺寸检查共同验证本次修复。

## SSE P0 修复与复验

原实现的 `subscribeCompanionState` 在 `reader.read()` 返回 `done` 后直接退出，异常只调用可选回调；`ChatView` 未传入错误回调，因此已挂载界面停留在最后快照。现已抽出独立的传输生命周期，保留原订阅 API 并增加可选传输状态回调。

实现与自动测试覆盖：

1. EOF、网络/HTTP/read 失败后的重连；500ms 起步、封顶 5s 的退避；首个有效快照超时为 10s。
2. 只在收到有效 Host 快照后报告 connected；无效事件不会解锁界面；新 Host 实例的较小 revision 可以被接收。
3. 保留消息和本地输入，重连提示可见；发送、Stop、附件、开关、会话操作在断流期间禁用；传输状态不写回 Host recovery 字段。
4. dispose 取消活动请求、reader 和 timer；迟到 fetch 响应关闭 body，无回调和重试；健康 idle 连接不轮询。
5. 独立连接使用新的解码 buffer，支持分块 LF/CRLF；旧连接的半个事件不会污染新快照。仅重新 GET 状态流，不自动重发聊天。

两轮真实 DSH Web 复验（含一次 DSH 冷启动）均通过：

| 检查             | 结果                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| EOF → 重连       | 第一条流发送旧快照后结束，第二条请求暂挂；重连提示可见，发送/开关/附件/会话操作均被禁用 |
| 消息与输入保留   | 暂挂期间原消息仍显示，可编辑输入；放行新流后输入内容不变，Host message IDs 不变         |
| 跨窗口一致性     | Host 开关在暂挂期间变化，新窗口先取得新值；放行 Dock 重连后两边取得相同新值，操作恢复   |
| 请求失败 → 重连  | 主动使首条 SSE 请求失败，第二条请求恢复新快照；message IDs 保持不变                     |
| 重试期关闭       | 首次 EOF 后关闭 Dock，等待 1.3s 没有新请求；重新打开正常连接                            |
| 不重发与页面健康 | 两轮均为聊天 POST 0 次、pageerror 0 次；测试只操作已有标记历史和开关，没有新聊天发送    |

首轮无分阶段记录的启动脚本曾等待超时，原因未定位；增加阶段记录后的同候选验收及再次冷启动均通过，未将这次超时归因为产品缺陷或宣称已修复其原因。截图已目视确认“重连提示 + 消息保留 + 禁用操作”和恢复后相同消息及输入仍可用。

边界：当前处理可观测的 EOF/error 和首快照超时；不新增服务端心跳，不对没有错误信号的静默链路作主动探测。
