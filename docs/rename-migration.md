## 1. 目标与选型

将面向用户的名称调整为 **DSH Chat Buddy**，npm 包名调整为 **`dsh-chat-buddy`**；副标题明确“在 DSH 中使用自己的 DeepSeek 网页账号聊天”。名称变化不表示新增其它模型或聊天服务。

| 方案                                      | 收益与代价                                               | 本计划建议                    |
| ----------------------------------------- | -------------------------------------------------------- | ----------------------------- |
| 只改显示名称，保留旧包名                  | 改动最少，但安装命令与产品名长期不一致                   | 不作为最终目标                |
| 改显示名与 npm 包名，保留内部标识和旧入口 | 品牌统一；需要一次显式迁移和新包发布，能避免搬动登录数据 | **推荐主线，RN-1 至 RN-3**    |
| 同时重命名所有接口、目录和仓库            | 外观整齐，但增加数据迁移、双实例和市场订阅中断风险       | 不采用全局替换；仓库另列 RN-4 |

新包版本暂建议 **`0.1.1`**，仅为计划参数，Review 后才能修改 `package.json`。旧 `dsh-deepseek-companion@0.1.0`、`v0.1.0`、RC-C 归档及其历史记录不改写、不重新发布。不能把旧包的验收结论直接当作新包通过。

已发布 npm 包不能直接改名，必须用新名字发布；旧包可以在迁移验证完成后另行考虑添加弃用提示，不删除旧包。依据：[npm 改名说明](https://docs.npmjs.com/unpublishing-packages-from-the-registry/)、[弃用机制](https://docs.npmjs.com/deprecating-and-undeprecating-packages-or-package-versions/)。上一轮公开查询未找到同名包，只是当时的观察，不保证发布时名称可用或有发布权限。
