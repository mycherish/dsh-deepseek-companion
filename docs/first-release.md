## 1. 发布目标与范围

先交付现有核心功能可用、故障处理可靠、界面简洁且符合 DSH 风格的版本，再扩展功能。首版包含一轮 UI 和轻动效收口，不等待 Proxy、Handoff、Task Brief 或 Desktop。原 Phase 21–23 延后；Phase 24 中的首版 UI 工作纳入 FR-3，首版 Regression / Release 由 FR-4、FR-5 承接。

“没有 bug”的发布标准是：承诺范围内没有未关闭的已知功能缺陷，发布矩阵通过，异常路径不会误发、重复发送、错误清空或串会话。测试通过不能证明不存在未知缺陷；后续发现的问题进入修复清单，不能靠修改验收口径关闭。

### 首版承诺

| 项目       | 范围                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 运行环境   | macOS 上的本地 DSH Web；`0.2.1-rc.2` 为主要验收基线，`0.1.5-rc.2` 为兼容基线；客户端以已验收 Chromium 为准，发布时记录具体版本 |
| 窗口       | Dock、页内 Float、浏览器 Pop-out；共享 Host 消息与状态，保持现有宽度所有权和单实例语义                                         |
| 登录与聊天 | 独立 DeepSeek 网页登录、文本流式、Markdown / 代码块、Deep Think、Search、Stop、新建聊天                                        |
| 图片与历史 | PNG / JPEG / WebP / GIF、图文及纯图片发送、历史切换、历史图片与加载失败文件名降级                                              |
| 恢复       | 可观测 SSE 断流重连、页面 / Chromium 恢复、30 s 共享 reconcile deadline、最多一次前端刷新、原地补全和会话删除确认；不自动重发  |
| 交付体验   | 用户能按公开安装步骤完成安装、Chromium 准备、首次登录、升级、回退和卸载；简洁 UI、主题 / 字体跟随及必要轻动效                  |

DSH 账号登录与 DeepSeek 网页登录是两套状态，不能宣传为登录 DSH 后自动拥有 DeepSeek 登录态。Search 来源仅展示真实取得的链接；结构化来源解析属于尽力恢复，不承诺每条搜索回答都有可点击来源。

### 首版之外

- 官方 Desktop、Windows / Linux、远程或无界面的 DSH 部署、未验收的宿主版本与其它浏览器。
- Proxy、Handoff、Task Brief、文档附件、多账号、浏览器池、Host 消息持久化、静默半开 SSE 主动探测。
- `parent_message_id=null` 的极快连续发送 identity 增强、树形 / 分支历史解析；当前继续保留消息并 safe-fail，不猜分支。
- 大型动画系统、装饰性常驻动画、额外主题系统与复杂个性化。网页 Provider、Gateway、伪 Function Calling、自动重发仍不在计划内。

这些边界必须在发布说明中可见。safe-fail 的可接受条件是保留数据、阻止不确定发送，并给出用户能够理解的下一步；若实际出现丢失、误发或重复，仍属发布阻塞问题。

1. **分发路径**：现有 README 主要描述本地 tarball + 人工 patch，不等于已经可以从市场安装。尚无公开包 / 索引发布和 Discover 安装证据。

4. **恢复提示**：既有真机记录显示恢复成功后仍残留 “Target page, context or browser has been closed” 旧请求错误。须复现并修复提示时序，同时保留仍有效的错误。
5. **视觉一致性**：现有界面已使用部分 DSH token，但还没有首版级主题、字号、键盘和三窗口一致性验收。Pop-out 目前只在打开时从根节点复制部分颜色变量，主题继承与实时变化需实测。
